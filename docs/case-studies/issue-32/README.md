## Problem Description

The repository maintained two parallel markdown files for each archived article:
- `article.md` — manually created from screenshots
- `downloaded.md` — generated by the automated download script (`download-article.mjs`)

The goal was to compare these files, identify remaining differences, find root causes, and if they match, consolidate to a single file by downloading directly to `article.md`.

## Root Cause Analysis

### Diff Results

| Article | Version | Differences | Root Cause |
|---------|---------|-------------|------------|
| Math introduction to Deep Theory | 0.0.0 | 2 lines (lines 7, 219) | Dynamic view count: 4829 → 4831 |
| Глубокая Теория Связей 0.0.1 | 0.0.1 | 2 lines (lines 11, 915) | Dynamic view count: 10566 → 10568 |
| The Links Theory 0.0.2 | 0.0.2 | 0 lines | Identical |

### Root Cause: Dynamic View Counts

The **only** differences between `article.md` and `downloaded.md` are **view count values** extracted from the live Habr page. These are dynamic metadata fields that increment with each page visit:

```
- **Reading time: 4 min | Difficulty: Hard | Views: 4829**
+ **Reading time: 4 min | Difficulty: Hard | Views: 4831**
```

```
- **Votes: +1 | Views: 4829**
+ **Votes: +1 | Views: 4831**
```

The view count appears in two locations per article:
1. Header metadata block (line ~7-11)
2. Footer statistics block (last ~5 lines)

### Why View Counts Differ

The `article.md` files were last generated by a previous download run, and `downloaded.md` was generated by a subsequent run. Between these two runs, the Habr pages accumulated additional views (2 views for articles 0.0.0 and 0.0.1). Article 0.0.2 had zero additional views between the two download runs, resulting in identical files.

## Screenshot Comparison

Visual comparison of the original Habr screenshots (`article-light.png`) against the markdown content confirms that all three articles accurately represent the original content:

- **Article 0.0.0** — All 12 figures, code blocks, formulas, and section headings match the original
- **Article 0.0.1** — All 10 figures, formulas (including blockquote formulas), and Russian text match
- **Article 0.0.2** — All 13 figures, code blocks, and mathematical notation match the original

The issue screenshot (`issue-screenshot.png`) shows a side-by-side comparison of article 0.0.2 on GitHub (dark mode) and Habr (light mode), confirming content parity.

## Solution Applied

### 1. Consolidated to Single `article.md` File

Since the content is identical (only dynamic view counts differ), we:
- Updated `article.md` with the latest content from `downloaded.md` for articles 0.0.0 and 0.0.1
- Removed all three `downloaded.md` files as redundant

The download script (`download-article.mjs`) defaults to writing `article.md`. The `--downloaded` flag has been removed since `downloaded.md` files are no longer used.

### 2. Files Changed

- `archive/0.0.0/article.md` — Updated view count (4829 → 4831)
- `archive/0.0.1/article.md` — Updated view count (10566 → 10568)
- `archive/0.0.0/downloaded.md` — Removed (redundant)
- `archive/0.0.1/downloaded.md` — Removed (redundant)
- `archive/0.0.2/downloaded.md` — Removed (redundant)

## Proposed Solutions for View Count Volatility

The dynamic view count issue means that re-running the download script will always produce a diff (due to views incrementing). Possible approaches:

### Option A: Exclude Dynamic Fields from Downloads (Recommended)

Modify `download-article.mjs` to omit volatile fields (views, votes, bookmarks, comments count) from the generated markdown. These values are ephemeral and not part of the article's intellectual content.

**Pros:** Deterministic output, clean diffs
**Cons:** Loses metadata snapshot

### Option B: Snapshot Dynamic Fields Once

Download dynamic fields once and then skip updating them on subsequent downloads, only updating the article content.

**Pros:** Preserves a historical snapshot
**Cons:** Snapshot becomes stale; adds complexity

### Option C: Store Dynamic Fields Separately

Move volatile metadata to a separate `metadata.json` file per article, keeping `article.md` purely for content.

**Pros:** Clean separation of concerns; `article.md` stays deterministic
**Cons:** Requires restructuring metadata handling

## Existing Tools and Libraries

Research into existing tools that could help with Habr-to-markdown conversion:

| Tool | Type | Key Feature | Relevance |
|------|------|-------------|-----------|
| [Turndown](https://github.com/mixmark-io/turndown) | npm | Customizable HTML→MD rules | Could replace custom extraction logic |
| [node-html-markdown](https://www.npmjs.com/package/node-html-markdown) | npm | High-performance HTML→MD | Fast bulk conversion |
| [@aiquants/html-to-markdown](https://www.npmjs.com/package/@aiquants/html-to-markdown) | npm | Playwright-based, handles SPAs | Handles dynamic content like Habr |
| [Microsoft MarkItDown](https://github.com/microsoft/markitdown) | Python | Multi-format to MD | General-purpose converter |
| [markdown-it-texmath](https://www.npmjs.com/package/markdown-it-texmath) | npm | KaTeX math in markdown | Math formula rendering |

The current custom Playwright-based approach in `download-article.mjs` is well-suited for Habr's specific needs (formula extraction from `img.formula` `source` attributes, figure captions, blockquote grouping). Generic tools like Turndown would need significant customization to match this level of accuracy.

## Key Technical Insights

1. **Dynamic metadata is the only source of article.md vs downloaded.md drift.** The download script produces byte-identical content for all static article elements (text, headings, code blocks, formulas, figures, links).

2. **View counts change by ~2 views per download session.** This is because the download and verification scripts each load the page, contributing to the view count.

3. **The `--downloaded` flag workflow was removed.** The download script writes directly to `article.md`, so `node scripts/download-article.mjs --all` updates the canonical files.

4. **Habr formula extraction via `img.formula[source]` is reliable.** The custom approach of reading LaTeX source from the `source` attribute of formula images produces accurate results that match the original rendering.

5. **Original Habr articles contain pre-existing bugs** (concatenated URL in Coq code, "LinksPlatfrom" typo) which the download script correctly preserves for archival accuracy.
